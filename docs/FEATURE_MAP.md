# Feature map

Where each feature from the project specification lives in the code. Useful when someone asks "show me where you implemented X".

All line references are to `js/app.js` unless stated otherwise.

---

## Data layer

| What | Where |
|---|---|
| Storage helpers with fallback | `lsGet`, `lsSet`, `load`, `save` |
| Reference data (categories, conditions, actions, areas) | `CATEGORIES`, `CONDITIONS`, `CONDITION_MEANING`, `ACTIONS`, `AREAS` |
| Seed listings | `SEED_ITEMS`, applied by `seedIfNeeded()` |
| Repurposing ideas content | `IDEAS` |
| Accessors | `items()`, `setItems()`, `requests()`, `setRequests()`, `users()`, `session()` |

---

## Feature 1 — Registration and login

| Part | Function |
|---|---|
| Sign-in / register modal and validation | `openAuth(mode, after)` |
| Header avatar and sign-out | `renderAuthSlot()` |
| Gate an action behind sign-in | `requireLogin(after)`, and the `after` callback in `openAuth` |
| Sign-in walls on protected pages | `VIEWS.post`, `VIEWS.dashboard` |

Email is checked with a regex, password minimum is 6 characters, duplicate emails are rejected.

---

## Feature 2 — Post an unwanted item

`VIEWS.post(opts)`

- Fields: name, category, condition, description, reuse option, pickup area, contact, photo
- Photo handling: `FileReader` → `Image` → `<canvas>` resize to 700px → JPEG at quality 0.7
- Validation: the `mark(id, valid)` helper toggles `.invalid` on each field wrapper
- On submit, the new item is unshifted onto `items()` and saved

CSS: `.form-card`, `.form-grid`, `.field`, `.err`, `.drop` in `styles.css`.

---

## Feature 3 — Four reuse options

- Definitions and colours: the `ACTIONS` object
- Colour tokens: `--donate`, `--exchange`, `--repair`, `--repurpose` in `:root`
- Rendered as chips by `actionChip(act)`
- Shown as cards on the home page inside `VIEWS.home` (`.actions-grid`)
- Chosen in the post form via the `.radio-set` radio group

---

## Feature 4 — Browse and search

`VIEWS.browse(opts)`

- Filter state object: `browseState`
- Filtering and sorting: the `apply()` function inside the view
- Reset: `reset()`, also wired to the empty-state button
- Search matches item name, description and category

---

## Feature 5 — Categories

`CATEGORIES` array. Category illustrations are generated by `catArt(cat, seed)`, which returns an inline SVG with a per-category palette and shape set.

---

## Feature 6 — Condition indicators

`CONDITIONS` and `CONDITION_MEANING`. The meaning is shown next to the condition in the item detail modal (`openItem`) and inside the post form's condition dropdown.

---

## Feature 7 — Give It a New Purpose

| Part | Where |
|---|---|
| Content | `IDEAS` array — 9 ideas with steps, time and difficulty |
| Grid page | `VIEWS.ideas` |
| Card artwork | `ideaArt(i)` |
| Detail modal with numbered steps | `openIdea(idx)` |

The "List an item for this" button in the modal calls `go("post", {presetAction:"Repurpose", presetName:i.from})`, which prefills the post form.

---

## Feature 8 — Contact the owner

| Part | Where |
|---|---|
| Item detail modal | `openItem(id)` |
| Request form | `openInterest(it)` |
| Duplicate-request guard | the `already` check in `openItem` |
| Owner's own listing guard | the `mine` check in `openItem` |

A request record is `{id, itemId, fromName, fromEmail, message, createdAt, status}` where status is `pending`, `accepted` or `declined`.

---

## Feature 9 — User dashboard

`VIEWS.dashboard(opts)`

| Tab | Data source |
|---|---|
| My listings | `mine` — items where `ownerEmail` matches the session |
| Requests received | `incoming` — requests whose item belongs to you |
| I'm interested in | `outgoing` — requests you sent |
| Completed | `myDone` — your items with `status === "completed"` |

Row rendering: `reqRow(r, side)`. Accept, decline, mark handed over and remove all mutate storage and re-render via `go("dashboard", {tab})`.

---

## Feature 10 — Environmental impact dashboard

`VIEWS.impact()`

| Part | Where |
|---|---|
| Headline counters | the `stats` object — demo `base` plus live counts |
| Monthly activity chart | `lineChart(data)` — hand-built SVG path, area fill and labels |

## CSS organisation (`css/styles.css`)

Sections are commented in order: tokens → header → buttons → hero → sections → item cards → browse toolbar → ideas → stats and charts → dashboard → forms → modal → toast → responsive.

Colours are all CSS custom properties on `:root`, redefined for `[data-theme="dark"]` and for `@media (prefers-color-scheme: dark)`. Changing the palette means editing the token block at the top and nothing else.
